# Развитие карт, сюжета и AI

## Карты

Исходные карты лежат в `data/maps`. Дополнительные пользовательские JSON загружаются из `user://maps` при открытии выбора миссий. `id` должен быть уникальным; совпадение с встроенным не подменяет встроенную карту.

```json
{
  "id": "outpost",
  "title": "04 / ЗАБЫТЫЙ ФОРПОСТ",
  "subtitle": "Новая глава",
  "briefing": "Захватите промышленный узел.",
  "debrief": "В архиве обнаружен новый маршрут.",
  "next": "core",
  "width": 64,
  "height": 24,
  "seed": 42,
  "resources": 25,
  "ai": "tactician",
  "capture_ticks": 144,
  "day_ticks": 288,
  "buildings": [
    {"kind": 0, "x": 8, "y": 12, "owner": 0},
    {"kind": 0, "x": 54, "y": 12, "owner": 1},
    {"kind": 4, "x": 26, "y": 8, "owner": -1}
  ],
  "elements": [[6, 32, 18]],
  "starting_robots": [{"owner": 0, "x": 12, "y": 16, "parts": 138}],
  "story": [
    {"id": "intro", "tick": 35, "text": "Кестрел, мы видим вашу отметку."},
    {"id": "discovery", "factories": 1, "text": "Завод подключён. Продолжайте движение."}
  ]
}
```

`owner`: 0 — человек, 1 — Инсигниане, −1 — нейтральный. `kind`: 0 — база, 1 — электроника, 2 — ядерные заряды, 3 — фазеры, 4 — ракеты, 5 — пушки, 6 — шасси. Координаты здания указывают на вход; его корпус простирается в сторону уменьшения `y`.

`elements`: `[тип,x,y]`, элемент занимает четыре клетки `(x,y)`, `(x+1,y)`, `(x,y-1)`, `(x+1,y-1)`. Типы 2–5 — неровная поверхность, 6–7 — обломки, 8–11 — возвышенности, 12–14 — низкие препятствия для антиграва, 17–18 — непроходимые руины, 21 — ограждение. Подходы к входам освобождаются при загрузке. Проверьте связность доступных путей для всех шасси: валидатор проверяет формат, но не гарантирует проходимость или баланс.

Размеры: 24–1024 по `width`, 12–128 по `height`. При подготовке новых глав используйте умеренные размеры: длинная исходная карта рассчитана на продолжительную партию. Каждой стороне нужна хотя бы одна база.

## Состав робота

`parts` — битовая маска:

| Значение | Модуль |
|---:|---|
| 1 | Бипод |
| 2 | Гусеницы |
| 4 | Антиграв |
| 8 | Пушка |
| 16 | Ракеты |
| 32 | Фазер |
| 64 | Ядерный заряд |
| 128 | Электроника |

Сложите значения выбранных модулей. Например, 138 = гусеницы + пушка + электроника. Одно шасси и 1–3 оружия обязательны.

## Сюжет

`briefing`, `debrief`, `next` связывают главы. В `story` событие с уникальным `id` срабатывает один раз, когда выполнены все его условия: минимум `tick` тактов и минимум `factories` принадлежащих игроку заводов. Сработавшие события сохраняются в партии. Тексты появляются в радио-строке.

В `main.gd/show_result` находится текущая развилка последней главы: сохранённый архив при отсутствии разрушенных баз, иначе частично утраченный архив. Здесь можно добавить новые условия завершения и выбор следующей главы. Сейчас базовая цель всех карт — лишить противника баз.

## AI

`src/ai/commander.gd` выбирает стратегию и выдаёт приказы, не обращаясь к 3D-сцене. `src/simulation.gd` исполняет приказы, обрабатывает бой, локальную навигацию и экономику. Все стратегические решения получают доступ к одному экземпляру симуляции и его RNG; не вызывайте глобальный `randf()`, если нужна воспроизводимость сохранений.

`data/ai_profiles.json` настраивает частоту решений, радиус обороны, размер группы для наступления и запас общих ресурсов. Модули строящихся машин сейчас заданы списками масок в стратегическом AI. Для нового семейства поведения добавьте ветку в `Commander.update`, профиль JSON, вариант в интерфейсе выбора и разрешённый идентификатор в `Simulation.valid_map`.

Тактическое движение использует `AStarGrid2D` с отдельной картой доступности для каждого шасси. Движущиеся роботы проверяются при выполнении шага; при занятости следующей клетки используется локальный обход. Это не сложная кооперативная маршрутизация.

## Архитектура и тесты

Рендер получает состояние симуляции и события `shot`, `hit`, `explosion`, `nuclear`, `capture`, `radio`. Он не принимает боевых решений. Фиксированный такт — 0,2 секунды; визуальные объекты интерполируются каждый кадр. Сохранение включает RNG, цели, таймеры, снаряды, захват, ресурсы, разрушения и сюжетные флаги.

Для новой механики добавьте сценарный тест в `tests/test_simulation.gd`: например, достижение цели при обходе препятствия или сохранение/восстановление в середине захвата. Не подменяйте проверку соответствия оригиналу тестом, который просто повторяет формулу реализации.

`tools/import_original.py` воспроизводимо читает оригинальные таблицы из локальной копии дизассемблера. Он также генерирует исходные версии трёх новых карт; не запускайте его после ручной правки этих файлов без сохранения изменений.
